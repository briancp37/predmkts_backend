### cross_run_dedup (2026-02-02)
- Integrated `select_snapshot_and_deltas()` into the Silver CLI `_run_process` loop
  - Applied per-day: within each day's manifests, the latest snapshot supersedes all prior deltas
  - Dry-run output also reflects snapshot/delta selection with `[snapshot]`/`[delta]` labels
- Cross-run dedup was already handled at Iceberg level by `merge_to_iceberg()` (upsert on merge keys)
- `bronze_run_id` metadata field already tracks which run contributed each record
- State tracking (`SilverStateStore`) already ensures idempotent reprocessing
- 4 new tests in `test_silver_cli.py`:
  - `test_snapshot_supersedes_prior_deltas` — delta before snapshot is skipped
  - `test_all_snapshots_no_deltas_skipped` — only latest snapshot processed
  - `test_reprocessing_same_manifest_is_idempotent` — second run skips via state
  - `test_dry_run_shows_snapshot_selection` — dry-run reflects filtering
- Updated `FakeDiscoveredManifest` test helper with `snapshot_type` and `manifest.generated_at`
- All 62 silver tests pass; mypy clean

### late_arrival_handling (2026-02-02)
- Iceberg already supports writing to old `event_ts` partitions natively via `DayTransform` partitioning — no changes needed
- Added late-arrival detection in `processor.py`: after normalization, scans for records with `event_ts` >7 days old and emits a `late_arriving_data` structured warning log with count, oldest timestamp, and age in days
- Warning is non-blocking — late data is still written successfully to the correct partition
- Late-arrival tolerance window: quality checks allow `expected_date ±1 day`; the >7 day warning is informational only
- 2 new tests in `test_silver_processor.py`:
  - `test_late_data_logs_warning` — verifies warning emitted for data >7 days old
  - `test_late_data_still_written_successfully` — verifies late data is written (not blocked)
- All 242 silver tests pass; mypy clean
