## Notes

Context: The polymarket-trades EventBridge schedule (rate(5 min), calling `ingest polymarket-trades`)
is being replaced with a polymarket-order-filled schedule that runs the incremental catchup command.
The CLOB API client and `ingest polymarket-trades` CLI command are kept as manual tools but removed
from scheduled execution.

Key design decision: ECS-based concurrency guard chosen over S3 lock files. The guard reads ECS
task metadata to detect if another task with the same command is already running, and skips if so.
This prevents overlapping runs when a catchup takes longer than the 5-minute schedule interval.

Prerequisite work already done in sprint 10 (incremental_catchup):
- `backfill catchup --platform polymarket --entity order_filled` command exists and works
- Timestamp-incremental logic via find_latest_manifest_source() is implemented
- ingest_order_filled() supports since_timestamp parameter

  (was incorrectly saying "already up to date" when today's partition existed)
