2026-01-30: Completed latest_timestamp_discovery category
- Created src/prediction_data/storage/discovery.py with two async functions:
  - find_latest_timestamp(s3_client, platform, entity) -> int | None
    Scans S3 for the latest date partition, finds the latest run by generated_at,
    checks for latest_timestamp in source metadata (not yet written by any ingestion),
    falls back to downloading data files and scanning for max timestamp field.
  - find_latest_date(s3_client, platform, entity) -> str | None
    Simple helper to find the latest dt= date partition for a platform/entity.
- Exported both functions from storage/__init__.py
- Added tests/test_discovery.py with 11 unit tests covering:
  - No data / no date partitions / no manifests → returns None
  - Fallback data scan (manifest without latest_timestamp field)
  - Multiple dates picks latest
  - Multiple runs picks latest generated_at
  - No data files → returns None
  - Records without timestamp field → returns None
  - find_latest_date with single/multiple dates
- All 419 tests pass, mypy clean, ruff clean
- Note: The Source pydantic model does not yet have a latest_timestamp field.
  That will be added in the incremental_order_filled category when manifests
  start writing latest_timestamp into source metadata.

2026-01-30: Completed incremental_order_filled category

  - since_timestamp forwarded to Goldsky client

  - Manifest latest_timestamp is None when no events fetched

2026-01-30: Completed catchup_command category
- Added `backfill catchup` command to cli/main.py with options: --platform, --entity, --bucket, --dry-run
- Three execution paths based on entity type:
  - order_filled (incremental): uses find_latest_timestamp(), calls ingest_order_filled(since_timestamp=...)
  - Date-scoped (trades): uses find_latest_date(), backfills missing days to today via _run_backfill()
  - Catalog (markets, events): uses find_latest_date(), runs fresh snapshot for today if not present
- Skips with message when no existing data found (user should run initial backfill first)
- Skips with message when already up to date
- Dry-run mode prints what would be fetched without executing
- Continues on failure per entity, collects errors, reports summary and exits non-zero
- Resolves bucket from --bucket flag or BRONZE_BUCKET env var (errors if neither set)
- Added 10 unit tests in TestCatchupCLI covering:
  - Invalid platform/entity validation
  - Missing bucket env var
  - Dry-run for order_filled (incremental) and trades (date-scoped)
  - Skip when no existing data / already up to date (trades and catalog)
  - Actual incremental execution for order_filled
  - Failure continues to next entity
- All 433 tests pass, mypy clean
