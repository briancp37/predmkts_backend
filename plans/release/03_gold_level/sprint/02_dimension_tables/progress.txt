## Notes
- The default YAML path resolves relative to canonical.py's location (3 parents up = repo root).
  This works for installed and editable installs but would need adjustment if the package
  were distributed as a standalone wheel without the mappings/ directory.
- Next priority: cli_and_testing (--dry-run support already exists; need integration tests and full pipeline verification).
- The load-dims CLI is extensible: LOADABLE_DIMS tuple in gold.py controls which tables are available.
  Add new loaders to dimensions.py and register them in the CLI dispatch.
- dim_market uses CanonicalResolver — ensure mappings/market_links.yaml is populated before
  production runs if cross-platform canonical IDs are needed.
- The ClickHouse insert for dim_market passes dicts via to_pylist(). For very large market catalogs
  (~360k rows), consider batching the insert if memory becomes an issue.
