### 2026-02-05: PnL Reconciliation Tests (Category: pnl_reconciliation)

Implemented comprehensive PnL reconciliation test suite verifying accuracy with known trade sequences:

**New test file:** `tests/test_gold_pnl_reconciliation.py` (20 tests)

Test coverage:
1. **Test Case 1 - Simple Buy-Sell Cycle:** Buy 100 @ $0.50, sell 100 @ $0.70 → verified $20 PnL
2. **Test Case 2 - Multiple Buys, Partial Sell:** Verified weighted average cost basis calculation
   - Buy 100 @ $0.50, Buy 50 @ $0.80 → avg_cost = $0.60
   - Sell 60 @ $0.75 → PnL = 60 * (0.75 - 0.60) = $9
3. **Test Case 3 - Position Flip:** Long to short via oversized sell
   - Buy 100 @ $0.50, Sell 150 @ $0.70 → close long PnL = $20, open short 50
   - Buy 50 @ $0.60 → close short PnL = $5
   - Total verified: $25
4. **Test Case 4 - Concurrent Positions Multiple Markets:** Same wallet trading in MKT_A (+$20) and MKT_B (-$10)
   - Verified separate position tracking
   - Verified aggregated wallet PnL = $10
5. **Ledger to wallet_pnl_daily Reconciliation:** Verified sum of per-fill realized_pnl_this_fill_usd equals wallet_pnl_daily total
   - Single wallet reconciliation
   - Multi-wallet reconciliation
   - Reconciliation with fees

Additional test coverage:
- Multiple partial closes with mixed wins/losses
- Reopen position after close (fresh cost basis)
- Short position PnL (profit when price decreases)
- Edge cases: price at 0 (total loss), price at 1 (max profit), fractional quantities, breakeven trades, high fees turning profit to loss

All hand-calculated expected values documented in test docstrings.

### 2026-02-05: Data Quality Validation Tests (Category: data_quality_validation)

Implemented comprehensive data quality validation test suite for all Gold tables:

**New test file:** `tests/test_gold_data_quality.py` (33 tests)

Test coverage organized by data quality constraint:

1. **Primary Key Validation (TestNoPrimaryKeysNull):**
   - wallet_position_state: (wallet, platform, market_id, outcome_id) non-null
   - wallet_position_ledger: (ts, wallet, platform, market_id, outcome_id) non-null
   - market_mark_daily: (platform, market_id, outcome_id, day_utc) non-null
   - wallet_pnl_daily: (day_utc, wallet) non-null

2. **Position State Constraints (TestPositionStateNoZeroQty):**
   - Open positions have qty != 0
   - Closed positions have qty = 0
   - positions_to_arrow includes closed for ReplacingMergeTree collapse
   - Downstream queries should filter qty != 0

3. **Wallet PnL Constraints (TestWalletPnlDailyNoZeroTradesCount):**
   - Aggregation produces trades_count > 0
   - Empty ledger produces zero PnL rows (sparse output)
   - All wallets have nonzero trades_count

4. **Market Mark Price Bounds (TestMarketMarkDailyPriceBounds):**
   - mark_price within (0, 1) for prediction markets
   - last_trade_price within [0, 1]
   - Edge case: price = 0 (resolved NO)
   - Edge case: price = 1 (resolved YES)
   - Multiple markets all within valid bounds

5. **Parquet Schema Conformance (TestParquetSchemaConformance):**
   - POSITION_STATE_SCHEMA conformance (including empty tables)
   - LEDGER_SCHEMA conformance (including empty tables)
   - MARKET_MARK_DAILY_SCHEMA conformance (including empty tables)
   - WALLET_PNL_DAILY_SCHEMA conformance (including empty tables)

6. **Additional Data Consistency (TestDataConsistencyConstraints):**
   - cost_basis_usd = abs(qty) * avg_cost for positions
   - avg_cost > 0 for open positions
   - qty_delta > 0 in ledger (direction in side field)
   - price in [0, 1] for prediction market fills
   - fees_usd >= 0 in ledger
   - volume_usd_24h >= 0 for market marks
   - trades_count_24h > 0 when volume_usd_24h > 0
   - wins + losses <= trades_count (breakevens fill gap)
   - volume_usd = sum(abs(qty_delta * price))
