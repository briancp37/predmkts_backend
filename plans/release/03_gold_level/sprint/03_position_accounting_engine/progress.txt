### accounting_engine (2026-02-04)
- Created `src/prediction_data/gold/accounting.py` with `PositionState` dataclass
  and `FillResult` result type.
- Fields: wallet, platform, market_id, outcome_id, qty, avg_cost, cost_basis_usd, last_fill_ts.
- Implemented `apply_fill(side, qty_delta, price, fees, ts)` method with:
  - Buy logic: weighted average cost = (old_qty * old_avg_cost + delta * price) / new_qty
  - Sell logic: realized_pnl = qty * (price - avg_cost) - fees, avg_cost unchanged
  - Position closing (qty -> 0): emits final PnL, FillResult.closed = True
  - Position flipping (long -> short via oversized sell): splits into close + open
  - Short position support: negative qty, symmetric PnL computation
- 27 unit tests in `tests/test_gold_accounting.py` covering:
  - Basic open/close, multiple buys, partial sells, exact close, breakeven
  - Position flip long->short and short->long
  - Fees on sells, partial sells, flips, and buys (cost_basis impact)
  - Complex multi-fill sequences with cumulative PnL tracking
  - Edge cases: small quantities, price at 0, price at 1
  - Input validation: invalid side, non-positive qty_delta
- All 27 tests pass. mypy strict mode clean. ruff clean.

### trade_to_fills (2026-02-04)
- Created `src/prediction_data/gold/fill_splitter.py` with:
  - `Fill` frozen dataclass: ts, wallet, platform, market_id, outcome_id, side, qty_delta, price, fees_usd
  - `nonusdc_side_to_outcome_id(market_id, nonusdc_side)`: maps "token1" → "{market_id}_0", "token2" → "{market_id}_1"
    Uses the same deterministic formula as dim_outcome in dimensions.py.
  - `split_trade_to_fills(trade, platform)`: splits one Silver trade dict into (maker_fill, taker_fill) tuple.
    Maker fill: wallet=trade["maker"], side=trade["maker_direction"].
    Taker fill: wallet=trade["taker"], side=trade["taker_direction"].
    Both fills share the same ts, market_id, outcome_id, qty_delta (token_amount), and price.
    fees_usd defaults to 0.0 (Polymarket fees are not in the Silver trades schema).
  - `trades_to_fills(trades, platform)`: batch conversion, returns all fills sorted by timestamp.
- 25 unit tests in `tests/test_gold_fill_splitter.py` covering:
  - Outcome ID mapping: token1→_0, token2→_1, invalid side raises ValueError
  - Single trade → 2 fills: maker/taker fields, shared timestamp/outcome/qty/price
  - Direction variants: maker sells + taker buys, maker buys + taker sells
  - Custom platform override, frozen immutability, missing field raises KeyError
  - Batch conversion: empty input, correct count, timestamp sorting, stable same-ts, mixed outcome IDs
  - Integration with accounting engine: fills feed into PositionState.apply_fill correctly,
    round-trip buy→sell sequence produces expected realized PnL

### position_ledger (2026-02-04)
- Created `src/prediction_data/gold/ledger.py` with:
  - `LEDGER_SCHEMA` (PyArrow): ts, wallet, platform, market_id, outcome_id, side,
    qty_delta, price, fees_usd, qty_before, qty_after, avg_cost_before, avg_cost_after,
    realized_pnl_this_fill_usd. Timestamps stored as microsecond UTC.
  - `LEDGER_COLUMNS`: ordered column name list for ClickHouse insert compatibility.
  - `LedgerRow` frozen dataclass: immutable record of a single fill's before/after state.
  - `record_fill(position, fill)`: captures position state before the fill, applies the fill
    through the accounting engine, captures state after, and returns (FillResult, LedgerRow).
  - `LedgerWriter` class: accumulates LedgerRow objects, converts to PyArrow Table via
    `to_arrow()`, and writes to S3 Gold Parquet + ClickHouse via `flush()`.
    - `record(position, fill)`: applies fill, records ledger row, returns (FillResult, LedgerRow).
    - `flush(gold_bucket, day, ...)`: idempotent write to S3 Gold (partitioned by day) and CH.
    - `clear()`: discard accumulated rows.
    - `count` / `rows` properties for inspection.
    - Supports `dry_run` mode (log but don't persist).
  - `build_ledger_for_day(fills, positions)`: convenience function that processes a sorted list
    of fills through the accounting engine, creating PositionState objects as needed, and returns
    (LedgerWriter, positions_dict). This is the main entry point for the batch_processor.

- Created `src/prediction_data/gold/position_state.py` with:
  - `POSITION_STATE_SCHEMA` (PyArrow): 9 fields matching the ClickHouse DDL.
    Timestamps stored as microsecond UTC.
  - `POSITION_STATE_COLUMNS`: ordered column name list for ClickHouse insert compatibility.
  - `positions_to_arrow(positions)`: converts a dict of PositionState objects to a PyArrow
    Table. Includes all positions (open and closed) so ReplacingMergeTree can collapse stale
    rows. Skips positions with no last_fill_ts (never filled).
  - `write_position_states(positions, clickhouse_client, dry_run)`: converts positions to
    arrow and inserts into ClickHouse wallet_position_state table. Supports dry_run mode.
  - `read_position_states(clickhouse_client)`: reads current open positions from ClickHouse
    using FINAL keyword and qty != 0 filter. Returns dict of PositionState objects keyed by
    (wallet, platform, market_id, outcome_id). Used by batch_processor to load existing state.
- Added `first_open_ts` field to `PositionState` dataclass in `accounting.py`:
  - Set when a position is first opened (qty transitions from 0 to nonzero).
  - Cleared (set to None) when position is closed (qty goes to 0).
  - Reset to the flip timestamp on position flips (close + open in opposite direction).
  - Unchanged on subsequent fills to an existing open position.

### batch_processor (2026-02-04)
- Created `src/prediction_data/gold/trade_processor.py` with:
  - `process_day(dt, platform, gold_bucket, ...)`: main entry point that orchestrates
    the full pipeline for a single day:
    1. Reads Silver polymarket.trades via PyIceberg (date-filtered scan)
    2. Loads existing position state from ClickHouse via `read_position_states()`
    3. Splits trades into fills via `trades_to_fills()` (sorted by timestamp)
    4. Processes fills through accounting engine via `build_ledger_for_day()`
    5. Writes ledger to S3 Gold Parquet + ClickHouse via `LedgerWriter.flush()`
    6. Updates position state in ClickHouse via `write_position_states()`
    7. Records the day as processed in S3 state store (JSONL at
       `gold/_state/trade_processor/processed.jsonl`)
  - `process_date_range(start_date, end_date, ...)`: sequential processing of a date range
    (order matters for cumulative position state). Returns dict mapping dates to rows written.
  - Idempotency: checks S3 state store before processing; skips already-processed dates.
    Supports `force_reprocess=True` to override.
  - `dry_run` mode: logs what would be written but doesn't persist.
  - State store functions: `_load_processed_dates()`, `_mark_processed()`.
  - Summary logging: fills processed, positions updated, realized PnL total.
- Integrated with existing `gold CLI daily-run`:
  - `_run_daily_step("process-trades", ...)` in `cli/gold.py` now successfully imports
    and calls `process_day()` (was previously a placeholder raising NotImplementedError).
  - Updated `tests/gold/test_daily_run.py::test_process_trades_not_implemented` to
    `test_process_trades_step` — now verifies process_day is called with correct args.
- 28 unit tests in `tests/test_gold_trade_processor.py` covering:
  - State store: empty state, load dates, generic exception handling, entries without day
  - Mark processed: append to empty, append to existing, field verification
  - _compute_summary: empty writer/positions, buy-then-sell PnL verification
  - _read_silver_trades_for_day: PyIceberg call verification, empty result, custom platform
  - process_day: no trades returns 0, dry_run produces no writes, single trade → 2 fills,
    idempotency skip, force_reprocess, writes ledger and state, marks processed in state store,
    existing positions loaded from CH, multiple trades accounting, no gold_bucket skips S3
  - process_date_range: single day, multi-day, options passthrough
  - End-to-end: buy/sell PnL, round-trip with mock CH, daily-run CLI integration,
    state store round-trip

## Notes
- Next priority: cli — add `prediction-data gold process-trades` CLI command with
  `--dt`, `--start-date/--end-date`, `--force-reprocess`, and `--dry-run` flags.
  The batch_processor `process_day()` and `process_date_range()` functions are
  already fully implemented and ready to be wired into the CLI.
- The `gold daily-run` command already calls `process_day()` via `_run_daily_step()`.
  The `process-trades` CLI command will provide direct access for ad-hoc processing.
- fees_usd is set to 0.0 for all fills. Polymarket's Silver trades schema does not include
  per-trade fee data. If fee data becomes available later, the Fill dataclass and splitter
  already support it - just needs a source to read from.
- Closed positions (qty=0) are written to ClickHouse so that ReplacingMergeTree can
  overwrite stale open rows. Downstream queries use WHERE qty != 0 to exclude them.
- read_position_states() uses FINAL to get deduplicated results from ReplacingMergeTree.
- State store for trade_processor lives at `gold/_state/trade_processor/processed.jsonl`
  in the Gold S3 bucket. Each line records: day, processed_at, fills_processed,
  positions_updated, realized_pnl_total.
