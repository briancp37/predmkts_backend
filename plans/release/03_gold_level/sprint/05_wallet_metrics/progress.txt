### wallet_mtm_daily (2026-02-02)
- Created `src/prediction_data/gold/wallet_mtm.py`
  - Schema: day_utc, wallet, equity_usd, unrealized_pnl_usd, exposure_gross_usd, exposure_net_usd, positions_count, missing_marks_count
  - `_read_watchlist_wallets()` queries gold_watchlist FINAL for active wallets
  - `_read_positions_for_wallets()` reads from wallet_position_state (qty != 0)
  - `_read_marks_for_day()` reads market_mark_daily FINAL for mark prices
  - `compute_mtm_for_day()` groups positions by wallet, joins with marks, computes equity/unrealized/exposure
  - `compute_wallet_mtm()` orchestrates: watchlist → positions → marks → MTM → S3 + CH
  - Missing marks handled gracefully: logged at debug level, position skipped, counted in missing_marks_count
- Created ClickHouse DDL: `docker/clickhouse/init/009_wallet_mtm_daily.sql`
  - ReplacingMergeTree(version), PARTITION BY toYYYYMM(day_utc), ORDER BY (wallet, day_utc), TTL 90 days
- Added CLI command: `prediction-data gold compute-mtm --dt YYYY-MM-DD [--dry-run]`
  - Supports --start-date/--end-date for range processing
- 16 unit + CLI tests in `tests/gold/test_wallet_mtm.py`, all passing
- mypy clean, 883 tests passing (full suite)

### wallet_position_snapshot_daily (2026-02-02)
- Created `src/prediction_data/gold/wallet_position_snapshot.py`
  - Schema: day_utc, wallet, platform, market_id, outcome_id, qty, avg_cost, mark_price, position_value_usd, unrealized_pnl_usd
  - Per-position detail (unlike wallet_mtm_daily which aggregates to wallet level)
  - Reuses same helper pattern: _read_watchlist_wallets(), _read_positions_for_wallets(), _read_marks_for_day()
  - `compute_snapshot_for_day()` creates one row per position with mark-to-market values
  - `compute_wallet_position_snapshot()` orchestrates: watchlist → positions → marks → snapshot → S3 + CH
  - Missing marks: position skipped (logged at debug level)
- Created ClickHouse DDL: `docker/clickhouse/init/010_wallet_position_snapshot_daily.sql`

- Added CLI command: `prediction-data gold compute-position-snapshot --dt YYYY-MM-DD [--dry-run]`
  - Supports --start-date/--end-date for range processing
- 17 unit + CLI tests in `tests/gold/test_wallet_position_snapshot.py`, all passing
