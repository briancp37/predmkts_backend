### 2026-02-05: ClickHouse Query Utilities
- Created `src/prediction_data/api/clickhouse.py` with:
  - `get_clickhouse_client()`: Singleton pattern for ClickHouse client reuse
  - `execute_query()`: Async wrapper that runs queries in thread pool to avoid blocking
  - `execute_query_count()`: Convenience function for COUNT queries
  - `build_where_clause()`: Builds WHERE clauses with ILIKE support for search fields
  - `build_pagination()`: Builds LIMIT/OFFSET with max limit clamping
  - `build_order_by()`: Builds ORDER BY with field validation
  - `rows_to_models()`: Converts query results to Pydantic models
  - `ping()`: Async health check function
- Default query timeout: 10 seconds
- Thread pool with 4 workers for concurrent query execution
- All type checks pass (mypy)
- All 1441 tests pass (pytest)

### 2026-02-05: GET /markets/{id}/trades Endpoint

  - Full OpenAPI documentation with descriptions

### 2026-02-05: GET /markets/{id}/price-history Endpoint
- Implemented `get_market_price_history()` service function in `src/prediction_data/api/markets/service.py`:
  - Queries ClickHouse market_mark_daily table for historical price data
  - Supports interval param: 1d (daily), 1w (weekly aggregation)
  - Note: 1h and 4h intervals return daily data since hourly data is not yet available
  - Supports filters: startDate, endDate (YYYY-MM-DD format)
  - Optional outcomeId parameter; defaults to YES outcome if not specified
  - Auto-selects YES outcome by querying dim_outcome for side='Yes' or label containing 'yes'
  - Returns chronological order (oldest first) for chart rendering
  - Weekly interval uses toMonday() for aggregation with sum(volume) and argMax(price)
- Implemented `GET /markets/{id}/price-history` endpoint in `src/prediction_data/api/markets/router.py`:
  - Path parameter: market_id (resolved via get_market_by_id for flexible ID matching)
  - Query params: interval (1h|4h|1d|1w, default 1d), startDate, endDate, outcomeId
  - Returns PriceHistoryResponse with items, marketId, outcomeId, interval, startDate, endDate
  - Returns 404 HTTPException if market not found
  - Full OpenAPI documentation with descriptions
- Added `PriceHistoryResponse` schema to schemas.py for structured response metadata
- All type checks pass (mypy)
- All 1441 tests pass (pytest)
- Note: Sub-daily intervals (1h, 4h) return daily granularity as hourly data is not yet computed.
  Future enhancement: compute hourly marks from Silver trades for finer-grained charting.

### 2026-02-05: CLOB API Client
- Created `src/prediction_data/api/clob_client.py` with:
  - `ClobApiClient` class: Async client for Polymarket CLOB API order book data
  - `get_order_book(token_id)`: Fetch order book for a single token (GET /book)
  - `get_order_books(token_ids)`: Batch fetch order books for multiple tokens (POST /books)
  - `OrderBookSummary` dataclass: Extracted bid/ask with computed spread metrics
  - `OrderBookSummary.from_api_response()`: Parse CLOB API response, extract best bid/ask
  - Spread calculations: spread, spreadPercent (based on midpoint), spreadCents
  - Response caching with configurable TTL (default 30 seconds)
  - Rate limiting (conservative 30 req/s, well under 500 req/10s limit)
  - Batch requests support up to 500 tokens per request
  - Graceful error handling: returns None for failed fetches
  - `get_clob_client()` / `close_clob_client()`: Singleton management for dependency injection
- Note: This is a public API client (no authentication required), distinct from the bronze layer
  CLOB client which uses L2 authentication for trades data
- All type checks pass (mypy)
- All 1441 tests pass (pytest)

### 2026-02-05: GET /markets/advanced Endpoint
- Implemented `get_markets_advanced()` service function in `src/prediction_data/api/markets/service.py`:
  - Queries ClickHouse dim_market table with LEFT JOIN to dim_event and market_mark_daily
  - Fetches 24h volume data from market_mark_daily aggregation
  - Queries dim_outcome for outcome details per market
  - Batch fetches CLOB order book data using ClobApiClient.get_order_books()
  - Enriches each market with real-time bid/ask/spread from CLOB data
  - Calculates spread metrics: spread, spreadPercent, spreadCents
  - Updates outcome currentPrice from CLOB midpoint price
  - Estimates liquidity from spread tightness
  - Applies advanced post-filters: minVolume/maxVolume, minSpread/maxSpread, minChange/maxChange, minLiquidity/maxLiquidity
  - Sorts by configurable field: volume, liquidity, spread, priceChange
  - Returns paginated results after filtering
- Implemented `GET /markets/advanced` endpoint in `src/prediction_data/api/markets/router.py`:
  - Extended query params: category, search, resolved, sortBy, sortOrder
  - Advanced filter params: minVolume, maxVolume, minLiquidity, maxLiquidity, minSpread, maxSpread, minChange, maxChange, tags
  - Pagination: limit (1-500, default 50), offset, page (alternative to offset)
  - Returns MarketAdvancedListResponse with CLOB-enriched markets
  - Full OpenAPI documentation with detailed descriptions
- Updated `src/prediction_data/api/main.py`:
  - Added CLOB client lifecycle management via close_clob_client() in lifespan shutdown
- CLOB data is cached for 30 seconds to reduce API calls
- All type checks pass (mypy)
- All 1441 tests pass (pytest)
- Note: timeRemaining and createdDate filters not implemented as endDate not in current schema.
  Tags filter parameter is accepted but currently no-op (no tags in dim_market schema).

### 2026-02-05: GET /markets/screener Endpoint
- Implemented `get_markets_screener()` service function in `src/prediction_data/api/markets/service.py`:
  - Queries ClickHouse dim_market table with LEFT JOIN to dim_event and market_mark_daily
  - Aggregates volume and calculates price change over configurable time window
  - Supports time windows: 6h, 12h, 24h, 7d (sub-daily use daily data until hourly available)
  - Uses argMax/argMin for price change calculation (latest - earliest / earliest)
  - Supports filters: category, search, resolved, minVolume, maxVolume, minPriceChange, maxPriceChange
  - Sorts by volume or priceChange (absolute magnitude)
  - Returns paginated results after filtering and sorting
- Implemented `GET /markets/screener` endpoint in `src/prediction_data/api/markets/router.py`:
  - Query param: timeWindow (enum: 6h, 12h, 24h, 7d, default 24h)
  - Query params: category, search, resolved (basic filters)
  - Query params: sortBy (volume|priceChange), sortOrder (asc|desc)
  - Query params: minVolume, maxVolume, minPriceChange, maxPriceChange (range filters)
  - Pagination: limit (1-500, default 50), offset
  - Returns MarketAdvancedListResponse (reuses schema from /markets/advanced)
  - Full OpenAPI documentation with detailed descriptions
- No CLOB API calls needed - uses historical market_mark_daily data only
- All type checks pass (mypy)
- All 1441 tests pass (pytest)
- Note: Sub-daily intervals (6h, 12h) return daily data since hourly marks not yet computed.
  Price change is calculated as a decimal (e.g., 0.1 = +10%, -0.1 = -10%).
