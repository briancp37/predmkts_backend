- Applied rate limits to all routers:

  - `markets/router.py`: PUBLIC_RATE_LIMIT on all GET endpoints; CLOB_PROXY_RATE_LIMIT on /advanced (uses CLOB API)
  - `traders/router.py`: PUBLIC_RATE_LIMIT on all endpoints

### Request Logging (2026-02-05)
- Created `src/prediction_data/api/middleware.py` with `RequestLoggingMiddleware`:
  - Logs every request: method, path, status_code, duration_ms, client_ip
  - Extracts user_id from JWT token for authenticated requests
  - Uses structlog for structured JSON logging (production) or colored console output (dev)
  - Generates/propagates `request_id` for distributed tracing
  - Adds `X-Request-ID` header to all responses
  - Logs slow requests (> 1s) at WARNING level
  - Logs client errors (4xx) at WARNING level, server errors (5xx) at ERROR level
  - Marks sensitive endpoints (/auth/login, /auth/register, /auth/refresh) in logs
  - Stores request_id in request.state for use by exception handlers
- Integrated middleware in `src/prediction_data/api/main.py`:
  - Added RequestLoggingMiddleware as outermost middleware for accurate timing
  - Updated `_get_request_id()` to prefer request.state.request_id for consistency
- Log format includes: timestamp, level, logger name, request context fields
- Request start logged at DEBUG level (optional verbosity)
- Request completion logged at INFO/WARNING/ERROR based on status/duration

### Health Check Enhancement (2026-02-05)
- Created `src/prediction_data/api/health.py` with comprehensive health check module:
  - `HealthStatus` enum: healthy, degraded, unhealthy
  - `DependencyStatus` enum: up, down
  - `DependencyHealth` model: status, latency_ms, error (optional)
  - `HealthResponse` model: status, version, dependencies dict
- Implemented dependency health checks:
  - `check_postgres()` - async PostgreSQL ping via `SELECT 1`
  - `check_clickhouse()` - async ClickHouse ping (reuses existing `api/clickhouse.py:ping()`)
  - Both return latency_ms and error details on failure
- Added `compute_overall_status()` logic:
  - HEALTHY: all dependencies up
  - DEGRADED: non-critical dependencies down (e.g., ClickHouse)
  - UNHEALTHY: critical dependencies down (PostgreSQL)
- Implemented three health endpoints:
  - `GET /health` - Full health check with all dependency statuses
    - Returns 200 for healthy/degraded, 503 for unhealthy
    - Response: `{status, version, dependencies: {postgres: {...}, clickhouse: {...}}}`
  - `GET /health/ready` - Kubernetes readiness probe
    - Checks only PostgreSQL (critical for user operations)
    - Returns 200 if ready, 503 if not ready with reason
  - `GET /health/live` - Kubernetes liveness probe
    - Simple "alive" check, no dependency checks
    - Returns 200 if process is running (avoids restart loops)
- Integrated health router in `src/prediction_data/api/main.py`:
  - Added `from prediction_data.api.health import router as health_router`
  - Registered router at `/health` prefix
  - Removed old simple `/health` endpoint stub
- API version constant `API_VERSION = "0.1.0"` included in health response
